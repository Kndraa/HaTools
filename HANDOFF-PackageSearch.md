## 2. Rules for this work

- **No Claude attribution in commits**, by the owner's explicit request: no `Co-Authored-By: Claude` line, no "Generated with Claude Code" line. Use the PC's normal git identity. (The cloud commits above have "Claude" as the git author because of that environment's git config; the owner hasn't decided whether to rewrite them.)
- Don't bump `version` in `package.json`: merging the PR bumps it and publishes a release (`CLAUDE.md` > Releasing). Label the PR `minor` (a new tool), and only merge once the tool is finished, since the merge releases it.
- Every new file and folder needs its `.meta`, generated by Unity (open the package in a project, then commit what Unity wrote).
- Changes to the tool go with its section in `CLAUDE.md`, plus a dated note for decisions.
- Never change the user's project or VCC settings without asking first (`CLAUDE.md` > Conventions > Safety). Installing and removing packages count.

## 3. Open decisions: ask the owner, don't pick

1. **How to call the VPM Resolver.** Recommended: reflection, so HaTools still compiles when the resolver is missing or its API changed (the tool then shows a message). A direct reference would make an API change a compile error that takes every HaTools tool down, and CI couldn't compile it at all.
2. **JSON: Newtonsoft or our reader.** Recommended: declare `com.unity.nuget.newtonsoft-json` in `package.json` `dependencies` and delete `PackageSearch.Json.cs`. It costs nothing in VRChat projects (the resolver already depends on it), and Unity then installs it into the CI test project by itself. The alternative is keeping the reader (about 150 lines, no dependency). The owner asked why declare it if it's already there; the answer given: without the declaration, a project that lacks it fails to compile every HaTools tool, CI included.
3. **Adding a listing to the user's VCC** (`Repos.AddRepo`) when a package comes from a listing the VCC doesn't know, so the VCC can update it later. Recommended: ask on each install, default No, since it changes the user's global VCC settings.
4. Minor, still open: the tool's name ("Package Search" was a placeholder), and whether to rewrite the cloud commits' author.

## 7. The VPM Resolver in the real project

The cloud sessions could only read resolver **0.1.21 (August 2023)**, from `vrchat-community/examples-image-loading`. Before building Install, check the real one:

1. Version: `Packages/com.vrchat.core.vpm-resolver/package.json`. Does it still list `com.unity.nuget.newtonsoft-json`?
2. Dump the public API of the resolver's library with a **temporary** editor script (put it in the test project's `Assets/Editor/`, never commit it):

```csharp
using System;
using System.IO;
using System.Linq;
using System.Reflection;
using System.Text;
using UnityEditor;
using UnityEngine;

static class DumpVpmApi
{
    [MenuItem("Tools/Dump VPM API")]
    static void Dump()
    {
        var asm = AppDomain.CurrentDomain.GetAssemblies().FirstOrDefault(a => a.GetType("VRC.PackageManagement.Core.Repos") != null);
        if (asm == null) { Debug.LogError("vpm-core-lib not loaded"); return; }
        string[] types =
        {
            "VRC.PackageManagement.Core.Repos",
            "VRC.PackageManagement.Core.Types.UnityProject",
            "VRC.PackageManagement.Core.Types.Packages.VPMProjectManifest",
            "VRC.PackageManagement.Core.Types.Packages.VPMProjectManifest+VPMPackageInfoMinimal",
            "VRC.PackageManagement.Core.Types.Packages.VRCPackageManifest",
            "VRC.PackageManagement.Core.Types.Packages.IVRCPackage",
            "VRC.PackageManagement.Core.Types.Providers.IVRCPackageProvider",
            "VRC.PackageManagement.Core.Types.Providers.VPMPackageProvider",
            "VRC.PackageManagement.Core.Types.PackageChangesResult",
            "VRC.PackageManagement.Core.Types.PackageChangeset",
            "VRC.PackageManagement.Core.Types.PackageConflict",
        };
        var sb = new StringBuilder(asm.FullName + "\n");
        foreach (string name in types)
        {
            var t = asm.GetType(name);
            sb.AppendLine(t == null ? "MISSING " + name : t.FullName);
            if (t == null) continue;
            foreach (var m in t.GetMembers(BindingFlags.Public | BindingFlags.Static | BindingFlags.Instance | BindingFlags.DeclaredOnly))
                sb.AppendLine("    " + m);
        }
        File.WriteAllText("vpm-api.txt", sb.ToString());
        Debug.Log("Wrote vpm-api.txt in the project folder");
    }
}
```

## 8. Building Install, Remove and the Installed tab (after the decisions)

Plan as discussed, for whoever builds it:

- **Install:**
  - Build the package and providers:
    - for a package from a listing: a provider from that listing's JSON (`VPMPackageProvider.GetRepoList` + `Create`), plus `Repos.GetAll`, so dependencies can come from any listing the VCC knows;
    - for a package from a release: a `VRCPackageManifest` from the release's `package.json` with `url` set to the zip, added to a provider of its own (`AddPackage`).
  - Call `GetPackageChanges` first. Show the user what will be installed or updated and any conflicts or unmet dependencies, and ask before going on (v1: refuse with a clear message when a dependency can't be found in any provider).
  - Then call `AddVPMPackage` in `Task.Run` (its downloads block), with a progress bar. Back on the main thread, call Unity's internal `PackageManager.Client.Resolve` by reflection (as the resolver's own window does) and `AssetDatabase.Refresh()`.
- **Remove:** `RemoveVPMPackage(id, force: false)` after a confirmation. It refuses to remove a package another one depends on, and VRChat's SDK packages; say so.
- **Installed tab:** `VPMProjectManifest.Load(projectDir).locked`: name, pinned version, *Remove*. No network.
- **Rows:** a found package that is already in `locked` shows *Remove* (and its installed version) instead of *Install*.
- **Project folder:** `Directory.GetParent(Application.dataPath)`.
- **Tests:** keep dialogs in thin methods; test what can be tested without the resolver (building the package and provider inputs, reading `vpm-manifest.json` from a temporary folder, the messages). The resolver calls themselves can only be checked by hand in a real project, unless CI gets a copy of the resolver (VRChat's Distro licence allows free non-commercial redistribution; 0.1.21 can be fetched from `vrchat-community/examples-image-loading` during the CI run instead of being committed). Ask the owner before adding that.
- **Manual checks once built**, in the throwaway project:
  - [ ] install a package without dependencies (FaceEmo);
  - [ ] install one whose dependency is in the VCC (Modular Avatar needs NDMF from `vpm.nadena.dev`);
  - [ ] install one whose dependency can't be found: a clear message, nothing changed;
  - [ ] after each install, `vpm-manifest.json` has the package in `dependencies` and `locked`, the package folder is in `Packages/`, the Console is clean, and **the VCC's *Manage Project* page shows the same packages and versions**;
  - [ ] Remove, including refusing to remove a package another depends on;
  - [ ] the Installed tab matches the VCC.
- **Finally:** the `README.md` line, the full `CLAUDE.md` section (drop "in progress"), and delete this file and its `.meta`.
